# Резервы берём из состояния пула на конец шард-блока, источник заменяемый

Для всех DEX Pool snapshot — это состояние пула на конец шард-блока, прочитанное из его data cell (или через `get_pool_data`). Такое состояние worker уже получает при разборе блока, и один механизм работает и в live, и при бэкфилле из архива. Резервы из событий (DeDust v1/v2) используем только в тестах как проверку.

Снапшоты после каждой транзакции отвергнуты. После Catchain 2.0 блок идёт раз в ~0,4 с, дедупликация по блоку экономит лишь 20–35% строк, а внутриблочная точность для API не нужна. Взамен пришлось бы подгружать промежуточные состояния из celldb.

Источник резервов спрятан за интерфейсом на каждый DEX, поэтому переход на события или на состояние после каждой транзакции остаётся локальной заменой.
