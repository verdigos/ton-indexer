# Резервы берём из состояния пула на конец мастерчейн-блока, источник заменяемый

Для всех DEX Pool snapshot — это состояние пула на конец мастерчейн-блока, то есть после всех новых шард-блоков, которые этот блок фиксирует. Резервы читаются через `get_pool_data` (разбор data cell — возможная оптимизация). Ровно такое состояние worker уже получает: `BlockInterfaceProcessor` сводит состояния аккаунтов по мастерчейн-блоку, и один механизм работает и в live, и при бэкфилле из архива. Резервы из событий (DeDust v1/v2) используем только в тестах как проверку.

Снапшоты после каждой транзакции отвергнуты. После Catchain 2.0 блок идёт раз в ~0,4 с, дедупликация по блоку экономит лишь 20–35% строк (пока в basechain один шард, мастерчейн-блок и шард-блок практически совпадают), а внутриблочная точность для API не нужна. Взамен пришлось бы подгружать промежуточные состояния из celldb.

Источник резервов спрятан за интерфейсом на каждый DEX, поэтому переход на события или на состояние после каждой транзакции остаётся локальной заменой.
