# MCH C++ Runtime — Implementation Plan

Status date: 2026-07-06. Owner doc for finishing the MCH engine (Python + C++). Written to be
executable by a less-capable model: every task states its goal, exact files, verification
commands, and acceptance gate. Do tasks in order inside a phase; phases marked ∥ may run in
parallel by different agents ONLY with the stated file-ownership boundaries.

---

## 0. Ground rules (read before ANY task)

1. **Never break a green gate.** Before starting a task, run the full gate set (§1); after
   finishing, run it again. A task is not done while any gate is red. Gates are listed with
   exact commands — no substitutes.
2. **One semantics.** All expression/value behavior lives in `ton-mch-engine/src/ExprRuntime.*`.
   The interpreter (`ExprEval`) and all generated code call the same `rt_*` functions. Never
   implement a semantic twice. If codegen output disagrees with the interpreter, codegen is
   wrong (or you found an interpreter bug: STOP, report, do not silently fix).
3. **Python is ground truth.** The Python IR engine (`indexer/indexer/events/mch_ir/`) and
   evaluators (`indexer/indexer/events/mch/expr_eval.py`) define correct behavior. Docs can be
   stale; when doc and code disagree, code wins and the doc gap gets reported (not silently
   edited).
4. **A/B discipline.** Every C++ layer is verified by a byte-identical diff against a Python
   twin over the full fixture corpus (`indexer/tests/traces/*.lz4`, 147 files). New layers get
   new twins (scratchpad scripts, NOT committed to the repo). Dump formats use only
   cross-language-proven fields (btype/opcode/min_lt — never raw tx_hash strings unless the
   string form itself was A/B'd).
5. **No hot reload, ever** (user decision 2026-07-05). The IR artifact is loaded once at startup
   or embedded at build time. No reload/versioning/invalidation machinery.
6. **No cross-trace functionality, ever.** A trace is processed in isolation.
7. **IR JSON is the version-controlled contract.** Python emits it
   (`python -m indexer.events.mch.ir_emit`); committed copies live in
   `ton-index-worker/ton-mch-engine/ir/` (manual sync, documented in `ir/README.md`). The C++
   build never invokes Python — codegen is the C++ tool `mch-codegen`.
8. **Commits**: only when the user explicitly says so. One-line messages, no Co-Authored-By.
   Unrelated pre-existing working-tree changes stay OUT of MCH commits (hunk-split with
   `git diff | awk '/^@@/{h++} ...' | git apply --cached --recount` when a file mixes both).
9. **Windows build workflow** (critical, do not deviate):
   - Build ONLY via the wrapper: `cmd //c "<scratchpad>\build_mch.bat"` (vcvars64 + CLion cmake,
     target ton-mch-engine). If the scratchpad bat is gone, recreate it: call
     `"C:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat"`,
     then `"C:\Users\verdigo\AppData\Local\Programs\CLion\bin\cmake\win\x64\bin\cmake.exe"
     --build S:\Dev\ton-indexer-clear\ton-index-worker\cmake-build-debug-visual-studio
     --target ton-mch-engine` (add `--target mch-codegen` when needed).
   - NEVER run cmake configure under vcvars (libpqxx try_compile breaks). Configure happens in a
     plain environment (the IDE does it automatically on CMakeLists change).
   - After editing a CMakeLists: the first bat run may fail with a transient libpqxx
     "Permission denied" recompaction error — just re-run the bat once.
   - MSVC gotchas: `td::Slice` ctor is explicit (wrap `const char*`); `#include <iostream>` for
     std::cout; WIN32_LEAN_AND_MEAN is set repo-wide (do not remove).
10. **Python venv**: `S:\Dev\H-dump\tonscan-indexator\venv0\Scripts\python.exe`. Python tests
    run from `S:\Dev\ton-indexer-clear\indexer`.

## 3. Phase A — build-program design note (single agent, main-thread quality)

**Goal**: a written design (`docs/mch-cpp-buildprog-design.md`) for executing build programs
(parse/let/lookup/reject/failed/broken/flow/out/produces-switch) in C++, reviewed by the user
BEFORE implementation. Decisions to settle, each with recommendation + alternative:

1. **Async model.** `parse` is sync in C++ (TL-B adapters are pure), but `lookup` needs data
   access (interface repository equivalent) and Python batches lookups. Options:
   (a) two-phase collect→fetch→resume (mirrors the T32 paper design; matches actor model:
   collect lookup keys during a dry pass, actor-request them, resume with a filled table);
   (b) C++20 coroutines. Recommend (a): deterministic, testable offline (lookup table injected —
   exactly how the vectors already model lookups), no coroutine toolchain risk.
2. **Codegen vs interpret for statements.** Expressions already codegen. Recommend: statements
   also codegen (one `build_<matcher>()` fn per matcher emitted by `mch-codegen --builds`),
   with an interpreter fallback only if a debugging need appears. Statements are a small fixed
   set; straight-line emission mirrors the expr emitter.
3. **Env layout.** Extend `WhereEnv` shape: slots array (captures, slot-indexed — the walker
   already binds slots), locals from `let` become generated C++ locals (no runtime env needed),
   parsed bodies land in generated locals via `MsgParse` registry calls.
4. **BOC-bytes divergence** (vesting `message_boc_str`): pytoniq and td serialize the same cell
   tree with different container layouts (root hash equal). Decide: (a) root-hash parity bar
   for Cell-derived string fields (document per-field), (b) pytoniq-order BOC writer in C++,
   (c) switch Python to td-canonical bytes. Recommend (a) now, revisit if a consumer needs
   byte-equal BOCs.
5. **Merge + produced block**: build accept → `Block` from arena, btype from produces/switch,
   data = out-map (dict Value), then `merge_blocks(consumed)`; auto-append excess/bounce to the
   result list AFTER build (v1 parity, `pre_build_auto_append=False`). merge_blocks returning
   false == clean rejection (`[]`).
6. **Host bindings enumeration**: from the artifact, list every referenced pred / lookup /
   fn / shaper / builder / message-type with its C++ status (exists / TL-B tier / hand-write
   tier / blocked). This table drives Phase C/D scope. (Preds: 8 across 5 matchers; shapers: 1
   production user; fns: dedust legs/fail, tonstakers minted-nft, layerzero same-hash, tgbtc
   endian-hex; lookups: nft_item raw, jetton_wallet, nominator_pool, dedust_pool(s)…)

Acceptance: doc exists, user signed off on decisions 1-4.

## 4. Phase B — build programs in C++ (after A sign-off)

Tasks, in order:

1. **B1 — statement codegen** (`mch-codegen --builds <mch_ir.json>`): emit
   `BuildOutcome build_<matcher>(BuildEnv&)` per matcher with a build_program; BuildEnv =
   {slots, parsed-message accessors, lookup table ref, block refs}. `parse` → MsgParse registry
   call on the captured block's body (soft-parse: failure → statement-level effect identical to
   Python program.py); `let` → local; `reject/failed/broken when` → early returns/flags;
   `flow` → recorded flow ops (Phase E consumes); `out`/`switch` → data map + btype.
   Ground truth: `indexer/indexer/events/mch_ir/program.py` — port its execution order and

   (build the analog of expr vectors: `build_vectors.json`, committed in both repos' contract
   dirs like expr_vectors.json).
2. **B2 — lookup two-phase runtime**: collect pass (generated code runs with a "collector"
   lookup table that records keys and returns null), fetch adapter interface
   (`class LookupSource { virtual fetch(kind, key) -> Value; }`), offline implementation =
   fixture-backed table (the trace fixtures bundle interface data — same source the Python
   TestInterfaceRepository uses; write a loader for that section of the .lz4). Resume pass runs
   the real build. Gate: lookups resolve identically to Python on corpus fixtures.
3. **B3 — try_build end-to-end**: walker match → captures → build → merge → produced block +
   auto-append; engine loop = priority-ordered matchers over BFS with re-scan semantics ported
   from `engine.py` (read its loop; blocks produced mid-pass are visible to later matchers
   exactly as in Python). Gate: **full-classification A/B** — new dump `--classify` (produced
   block tree: btype/data/consumed/topology per matcher) vs a Python twin running the real IR
   engine `build_matchers` + process loop, 147 fixtures, diff 0, for the matcher subset whose

   needs lookup+pred…). Maintain an explicit skip table like the match-phase one; shrink it as

## 10. Standing hazards (memorize)

- Frontier diamond-dup deviation (BlockTree.h header) — suspect #1 on any future diamond A/B diff.
- BOC bytes: byte parity achieved via `pytoniq_to_boc()` in Value.cpp (pytoniq cell order emulated;
  the ref-layout divergence was real). CRC per call site: MsgParse payload bytes crc=true
  (jettons.py explicit `hash_crc32=True`), `b64(Cell)` crc=false (bare `to_boc()` defaults).
- Matcher ordering (T20): all specs default priority 100 → ties break on FILE NAME. Production
  artifact orders ethena_deposit BEFORE jetton_transfer (e<j), so a composed-btype matcher can
  never see blocks produced by a later-named matcher within one engine pass sequence. T26 /
  production wiring must review spec priorities (or ordering) — B3 classify worked around it by
  prefixing the decl-jettons file `a_`.
- Outer classify BFS visits siblings in CANONICAL (min_lt) order on both A/B sides — consistent
  with the substrate invariant, but NOT byte-order-identical to production Python
  event_processing (raw insertion order). Matters only when overlapping matches race on sibling
  order; revisit at Phase G production parity.
- `td::json_decode` mutates its buffer; JsonValue holds Slices into it — keep buffers alive
  (WhereExpr self-owned-buffer pattern is the template).
- Leaf `.data` in C++ mirrors a SUBSET (extra_currencies / ton_transfer comment omitted —
  reading them faults where Python yields a value; wire through MsgParse when first needed).
- Python `.gitignore` `[Bb][Uu][Ii][Ll][Dd]*` hides `indexer/events/mch/builders/` — `git add -f`.
- Envelope `.msg` fields the C++ loader doesn't decode fault (fwd_fee etc.) — extend TraceLoader
  when a spec first touches one.
- Skip tables must always be computed from the ARTIFACT (both sides), never from registry
  availability — that's what keeps twins honest.

### Approved backlog

0. **Generated files out of git, per-document outputs (first hygiene item).** Today only
   vectors + tlb outputs are CMake custom_commands; wheres/builds are regenerated MANUALLY
   (hence the verification swap cycle), and ALL outputs are written into the SOURCE tree and
   committed. Target: every codegen output → `${CMAKE_CURRENT_BINARY_DIR}/generated/`
   (include dir added, nothing committed, source tree immutable during build); wheres/builds
   get real custom_commands with PER-DOCUMENT outputs + distinct table symbols
   (`builds_vectors_gen` ← ir/build_vectors.json for the runner; `builds_artifact_gen` +
   `wheres_artifact_gen` ← ir/mch_ir.json for match/classify) — kills the manual swap cycle;
   runners select by the existing sha guard. Committed contract shrinks to ir/*.json +
   tlb/*.tlb + tool sources. Cost: codegen diffs invisible in review (mitigated by the
   byte-determinism gate + sha guards).

1. **D1 — Amount(None) → Null (both-sides wave, biggest cleanup).** Python's `Amount(None)` is
   an accident of an Optional field; C++ models it as a third equality regime
   (Value.h:50,83, Value.cpp:51-55,284-291, ExprRuntime.cpp:16-18,66-69,144-146,
   BlockTree.cpp:282). Cleaner: absent value = Null, normal null-propagation. Coordinated
   change: indexer expr_eval.py + mch_ir/expr.py, expr-vectors regen (Amount(None) cases),
   IR spec §7 note, C++ removal of make_amount_none + special-eq branches. Gates shift by
   regen, not by relaxation.
2. **Harness/runtime isolation (C++-only, no semantics):**
   - move `run_parse_dump` + render helpers (~160 LOC) out of MsgParse.cpp into a harness file;
   - split the ACTION dump-printing out of Classify.cpp's try_build before Phase E builds on it;
   - dedupe `block_key` (MatchRunner.cpp:20-29 local copy vs BuildDriver's);
   - **B-leak fix**: runtime `rt_eq` container fallback currently calls the ASYMMETRIC vector
     comparator `structural_equal` (ExprRuntime.cpp:107 → Value.cpp:274). Define container `==`
     in the IR spec, give the runtime its own symmetric implementation, keep structural_equal
     harness-only.
3. **Trivia sweep (~30 LOC):** dead `parse_never`/JettonBurnNotification registration
   (MsgParse.cpp:475-477,489); unread `MsgContent.hash` (TraceLoader.cpp:137). KEEP
   `op_index`/`btype_index` (IrLoader) — currently unconsumed but built for the production
   loop's anchor index (Phase G).
4. **Codegen optimization pass (lead review of generated code, 2026-07-07; schedule inside
   Phase G where a benchmark can prove it).** The emitter (`codegen/ExprCodegen.cpp`) produces
   correct-but-naïve code; all fixes are emitter-level, behavior-preserving, and verified for
   free by the existing byte-gates (vectors 91/91, classify/parse-dump diff 0 after regen).
   Ranked by impact (user-confirmed: 4a + 4b are the priority):
   - **4a. Static dispatch (highest).** Every emitted call goes through string-keyed runtime
     dispatch: `rt_call_builtin("account", vector<Value>{v4})` = std::map arity lookup +
     name if-chain + a heap-allocated args vector PER CALL; `rt_access_build(env, v, "msg")`
     = strcmp chain. The codegen knows builtin and accessor statically — emit direct calls
     (`rt_builtin_account(...)`, enum-dispatched accessors), no name strings, no arg vectors.
     Matters doubly because the SAME emitter produces where_expr code, which runs per
     (block × matcher) in the match loop — the production hot path.
   - **4b. Kill gratuitous Value copies (second).** Emitted `Value v2 = env.slots[0];` copies
     a ~120-byte struct (std::string + RefInt256 + Ref<Cell> + 2 shared_ptrs = 4 atomic
     refcount bumps) only to pass it to a `const Value&` parameter. Emit the ref expression
     directly (`rt_access_build(env, env.slots[0], "msg")`); locals only where a value is
     genuinely consumed twice.
   - 4c. `std::move` into `Fields::emplace_back` for dead temporaries; `fs.reserve(n)` (field
     count known at codegen time).
   - 4d. Function-local `static const` for constant argument lists (e.g. the
     `std::vector<std::string>{"CoffeeCreateVault"}` rebuilt on every `rt_parse` call).

5. **Dead-isinstance dual-dispatch wave (Python correctness, found by C++ testbed 2026-07-11 —
   REQUIRED before Phase G flips production to declarative jettons).** Shared build cores gate
   composed-block reads on `isinstance(x, JettonTransferBlock)` (and siblings). Under legacy
   producers (today's production AND the parity sweep's prereqs) the class is real and legs
   fill; under DECLARATIVE producers (C++ testbed, all-declarative future) the block is the
   canonical generic Block → branch dead → swaps silently emit EMPTY `dex_incoming/outgoing_
   transfer` and null sender/source_asset. First confirmed site: coffee swap core (12-line
   testbed diff when C++ naively filled from btype). The sweep CANNOT catch this class of bug
   — its prerequisite blocks always come from legacy matchers; only all-declarative
   composition (testbed classify) exposes it. Fix pattern: dual dispatch (isinstance OR
   btype+dict via `_dget`), exactly like the pairing passes got in the conversion wave.
   Site catalogue (cpp-twins waves 1+2, 2026-07-11):
   - blocks/swaps.py `build_coffee_swap_core` ~L1395 + ~L1424 — jetton in/out legs leave

## 12. BOC serialization parity — corpus evidence (2026-07-07, decision pending)

Question revisited (user): is byte-identity of BOC container bytes a real invariant, or a
serializer implementation detail? Empirical scan of ALL 1477 fixture message bodies (DB
provenance = td bytes written by the C++ indexer), re-serialized with pytoniq and compared
(scratchpad `boc_parity_scan.py` / `boc_divergence_deep.py`, session 50ed80b7):

- **Root hash equal 1477/1477.** Every serialization decodes to the identical cell tree.
- **Two divergence mechanisms, nothing else:**
  1. **CRC flag** — DB bodies carry td's CRC (flags byte 0x41), pytoniq default omits it
     (+4 bytes). Pure container framing. With `hash_crc32=True` matched, **1273/1477 (86%)
     are byte-identical** — td and pytoniq fully agree on linear-chain trees (typical
     jetton transfer + snake payload).
  2. **Topological cell order** — 204/1477 (14%): same cells (content multiset equal
     204/204), different container sequence + ref-index bytes. Occurs ONLY on branching
     trees (113 multi-ref, 91 shared-subtree; opcodes: w5 `0x7369676e` multi-action,
     multisig, coffee, jetton ops with branching payloads).
- **Why:** the BOC spec allows any topological order. pytoniq = last-visit DFS (verified
  exactly, 204/204 — `pytoniq_to_boc` is a correct clone). td = its own 3-phase weighted
  `reorder_cells`/`revisit` (boc.cpp:258-380, reverse-child iteration) — matches nothing
  textbook. Every implementation (td, pytoniq, ton-core JS, tonutils) picks its own order;
  none parity-chase another.
- **DB reality:** already mixed-provenance — bodies = td bytes with CRC, action payload
  fields = pytoniq bytes without. No consumer ever noticed: everything parses, nothing
  byte-compares. The DB invariant is **decoded-tree identity**, not bytes.

**DECISION ORDERED + DONE 2026-07-11 (session actions-port).** Switched the A/B parity bar for
Cell-derived output fields (jetton `forward_payload`/`custom_payload`/`stonfi_swap_body`,
vesting `message_boc_str`) from byte-equality to **root-hash equality**; C++ now uses
native `td::std_boc_serialize` (mode 0) everywhere and `pytoniq_to_boc` + `pytoniq_order`
are DELETED (P3 exponential-re-walk DoS gone). Comparators render such fields as
`cellhash:<HASH-UPPER>` — a shared `is_boc_field`/`boc_field_cellhash` in Value.cpp keyed by
field name (both C++ dump renderers + the 3 Python twins), decoding the b64 str / raw BOC
bytes to the cell root hash. `comment`/`bitcoin_txid`/`pubkey` are raw non-BOC bytes and
stay as-is. Python production unchanged (its pytoniq bytes remain valid under the same bar).
AUDIT CORRECTION (vs the original model): the Cell-derived fields render as `str:`/`b64:`
b64() output, NOT `b64:` uniformly — the field-keyed decode handles both. b64_cell expr
vector unchanged (single-cell td == pytoniq); no build-vector regen needed. All gates diff 0.
