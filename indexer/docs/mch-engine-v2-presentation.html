MCH IR Engine v2
the purpose-built walker

One .mch pattern language, compiled once to a language-neutral JSON IR, then interpreted directly by a hand-written abstract machine that binds captures during the walk — no legacy primitives, no post-hoc reconstruction, built as the line-for-line blueprint for the C++ port.

01 Context

92 hand-written matchers. One language should feed every host.

The classifier reads a blockchain trace — a tree of Block objects — and collapses protocol-specific shapes into typed actions. Today that logic lives in 92 registered BlockMatcher instances across ~23 protocol modules, all imperative Python.

The .mch DSL (spec v0.2) replaces those subclasses with declarative spec files. Behaviour parity across host languages is the load-bearing invariant: the same source must match identically in Python (prod), C++ (prod, future) and Go (POC).

M5 achieves parity structurally — one frontend compiles .mch to a neutral IR that every engine consumes, instead of N independent parser+compiler stacks that drift.

Ported so far

The tension: reusing legacy engine primitives to run the IR was fast to build but structurally wrong — it discards exactly the information the C++ port needs. v2 is the corrective rewrite.
02 One frontend, thin per-host interpreters

The compilation pipeline

The IR is disposable (schema note): v0.1-poc is the binding contract between the Python emitter and any loader — no .mch parsing ever happens outside Python. Re-emitting the same specs is byte-identical (verified).

No nulls, canonical order

  • Absent fields are omitted, never emitted as null.
  • Object keys in schema order, arrays in emission order — so two emits are byte-identical.
  • All indices are 0-based ints into the top-level nodes array.
captures are informational to the Go POC but load-bearing in v2 Python: the card table drives scalar-vs-list assembly (slide 17).
05 IR schema tour · the node graph

A flat node array wired by index edges

Six node kinds. Edges are node ids, not nesting — child, parent, children[], plus branches[] (or) and step/exit (recursive). Cycles are legal, so loaders wire in two passes: allocate every node, then resolve edges by id.

Common optional fields on any kind: optional, capture, where (named predicate) or where_expr (inline sync expression — mutually exclusive).

Same-name captures, two branches. peer (card many) is captured on both node 8 and node 10 — one pool hop per unrolling, whichever branch wins that round. This is why cardinality lives in the record, not the node.
06 IR schema tour · expressions & build programs

Two tiny tagged languages: k for expressions, s for statements

parse is soft, first-success-wins. types are tried in order; a body that fails to parse simply tries the next alternative and .body null-propagates.
where_expr is sync-only. It composes onto test_self, so lookups and host fns are rejected at load time — no I/O can hide inside a candidate test.
07 Build language · the fully declarative case

An 18-field out block — zero host code

What the language expresses natively

  • lookup — async interface-repo query (jetton_wallet), null-propagating.
  • ?? — soft fallback from the internal body to the transfer body.
  • ternary — A if cond else B receiver resolution.
  • reject / failed when — the match's reject + failed wiring.
  • flow (jetton_burn) — value_flow debit with a negative amount.
Honest boundary, noted in the spec: legacy marks the consumed anchor broken on an owner/receiver mismatch; the build language can only flag the produced block. It doesn't affect produced-block parity (legacy leaves that flag False) — and the comment says so in the source.
08 Build language · the escape hatch

When declarative isn't enough: host-fn residue

The declarative / imperative split

  • declarative — dex literal; the TON-in branch sender/source_asset off the raw call; the reject/failed decisions.
  • host fn dedust_swap_legs — peer-swap list assembly (lt-sort over the consumed set), jetton-branch in-leg, payout resolution, destination-asset pool-hop loop, nested leg dicts.
  • host fn dedust_swap_failed — notification-coverage scan.
Why the residue can't be language: no record literals (must build nested dicts), no list quantifiers (notification scan), and composed blocks have no reliable .msg — their event-node order is set-shuffled by merge_blocks. The escape hatch exists precisely for this.

Both files above round-trip in the parity sweep with zero divergences against their compiled counterparts.

09 Why a rewrite

The v1 tax: ~250 lines to rebuild what the walk already knew

v1 (461 lines) reused blocks/basic_matchers.py as its execution core. try_build returned a flat consumed-blocks list with no captures, no iteration structure, no rejection channel, and nondeterministic set() ordering — so most of the file existed only to reconstruct information the walk had already computed and thrown away.

11 Walk algorithm · match_node

Test → bind → edges, in a fixed order

Failure discipline

A failed sub-attempt may leave the context dirty. Only the caller's rollback cleans it — every edge helper marks before an attempt and rolls back on failure. The walk phase is fully synchronous: test_self and the entire match are pure; the single async boundary is the build phase (lookups / builders).

12 Walk deep-dive · child edge

Multi-match accumulation — not first-win

The legacy engine tried the child matcher on every child and consumed all full matches. Two matching children → both consumed. A scalar (one/opt) capture keeps the first binding.

Pinned by R4 test_r4_child_edge_consumes_all_matches_scalar_takes_first: two Bar children under one Foo → m.y is bar1, and _mch_consumed == [foo, bar1, bar2].

Easy to get wrong: the obvious "break on first match" would silently drop the second child from consumed and break merge_blocks.

13 Walk deep-dive · children set

Declaration order · first-match-wins · consuming working set

Each declared item takes the first candidate that matches and removes it from an independent working copy of next_blocks. Required items that find nothing fail the node; optional tails pass.

Overlap with the child edge is legal. The two edges scan independent copies, so the same block can satisfy both — ctx.consume's identity dedup absorbs the double-count (legacy dedups via merge_blocks(set(...))).

R5 covers all four traps: order, working-set removal, required-unmatched failure, optional tail — plus a hand-crafted child+children overlap artifact the frontend can't emit.

14 Walk deep-dive · alternation

or = first full subtree that builds, with savepoints

A branch may partially consume — bind captures, pull in children — and then fail deeper. rollback(mark) truncates bindings, consumed and frames and rebuilds the visited tail, so the next branch starts from a pristine context.

Pinned by R3. Branch 1 (Bar → Baz → Qux) consumes Bar+Baz then fails on a missing Qux; branch 2 (Bar) wins. Result: losing bindings are None, _mch_consumed == [foo, bar], and the rolled-back baz is never absorbed (baz.parent is None).
exclusive: the exclusive flag never appears here — it lives only in the head test (slide 20). As an edge target, an exclusive-or behaves exactly like a plain one.
15 Walk deep-dive · recursion frontier

Exit tried first per candidate · one step per round

The blocks consumed by a winning step, in consumption order, become the next round's frontier. Each round tries exit before step on every candidate.

16 Walk deep-dive · recursion captures (T18)

List captures are gap-aligned per iteration frame

  • step captures — one element per iteration; the branch that lost this round contributes None.
  • exit captures — appended once, after the step elements.
  • post-recursion captures — plain scalars, bind normally.

Ownership (step / exit / plain) per slot is computed at load by reachability over the step / exit subgraphs — the v1 _reachable_captures, now precomputed.

17 Walk deep-dive · aux absorption

Two levels of excess/bounce — merged vs appended

Per matched node — nested

After any node's edges succeed, it consumes every next_block that is a CallContract with opcode 0xd53276db (excess) or 0xffffffff (bounce). These go into consumed and get merged into the produced block. Nested nodes behave as if both flags are always true — v1 built nested matchers with default flags; IR nodes carry none.

Root matcher record — appended

The anchor block's own aux siblings are governed by include_excess / include_bounces and appended to the result list after a successful build — never merged, never before the build (a rejection must not have to strip them).

R8 asserts the subtle inherited difference: nested aux land in _mch_consumed and get .parent set to the produced block; root aux stay parent-less and are returned as separate list elements. include_*: false is respected at root only.

18 Walk deep-dive · the rejection channel

None is a mismatch. [ ] is a clean reject.

None
structural mismatch — anchor or pattern didn't match
[ ]
clean rejection — pattern matched, build declined
[b, …]
accept — produced block + auto-appended aux

A reject when firing, a host builder returning None, or an EvalError in a build expression all collapse to [] — logged, never aborting trace processing. No aux blocks are attached to a rejection, and the matcher is immediately reusable.

R7 proves a rejected matcher is reusable and can still succeed on the next block once its state flips.
19 Semantic archaeology

Rewriting against parity extracts undocumented behaviour

Two legacy behaviours contradicted the draft spec. The rewrite pinned each with a test and wrote it into the engine docstring — turning tribal knowledge into a written contract the C++ port must satisfy.

① Frontier exhaustion ignores a declared exit

Spec §4.6 said exhaustion should fail when an exit is declared. The legacy RecursiveMatcher succeeds whenever ≥1 step landed, regardless of exit presence — a declared exit that never fires just leaves its captures empty.

v2 follows legacy: return iter_index > 0.

test_frontier_exhaustion_leaves_exit_captures_empty

② ExclusiveOr's test_self is never consulted by try_build

ExclusiveOrMatcher overrides only test_self, which OrMatcher.try_build never calls. So the exclusivity count gate is inert as an edge target and only bites where head tests are consulted — recursion entry and nested head counts.

specs/stonfi_v2_swap.mch depends on this: its hop branches overlap by prefix and must resolve first-match-in-order.

test_r9_exclusive_gate_applies_at_recursion_head_test

The doc even records the correction: the original §4.4 draft gated match_node on the count unconditionally — that mispinned legacy, and the amendment note in the spec says so.

20 Determinism & concurrency

No set() iteration. Immutable matchers. Reentrant.

  • List-order everywhere — candidates, frontiers, branches, children iterate in existing list order. v2 introduces no reordering and never iterates a set(). (Global (min_lt, index) ordering is deferred — parity with the compiled path first.)
  • Traversal-order consumed — ctx.consumed is identity-deduped at consume time; _mch_consumed is that list verbatim, anchor first.
  • Two runs, identical output — same bindings, same consumed list. Asserted, not assumed.
  • Reentrant by construction — matcher objects carry zero mutable state after load; every attempt gets its own context (a C++ stack object). Traces can run concurrently.
Parity comparisons account for legacy's shuffle: the sweep compares consumed as multisets (sorted tx hashes) and captures field-by-field — the legacy set() ordering makes its list order meaningless, so v2's determinism is a strict improvement that still round-trips.

22 C++ portability & roadmap

The walker is a line-for-line C++ blueprint

Designed to translate literally

  • Slots are ints, edges are node indices, frames are tuples — no name lookups on the hot path.
  • The entire match phase is synchronous and pure; the single async boundary is the build phase (lookups / builders).
  • _MatchContext = a stack object; CompiledNode/IrMatcher immutable → the C++ engine can run traces concurrently.
Go POC already proved the structural half: loads the same artifact and reports A/B-identical "Fired matchers" on three validated fixtures (KYQfjYD1…, C7bHOfSr…, c8jOrHqy…).

Follow-ups (deliberately out of this change)

  • JSON-Schema loader validation — structural checks beyond the hand-rolled loader.
  • Single sync evaluator + 3-phase batched lookups — collapse the async boundary into one batched round.
  • Retire the compiled path — frontend emits IR only; one engine per host.
  • T21 global ordering — candidates by (min_lt, index).
  • The C++ port — translate CompiledNode / _MatchContext / match_node directly.
Scope discipline: the doc lists each of these as explicitly not bundled — v2 replaces only engine.py's internals behind a pinned public API.
