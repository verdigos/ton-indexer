## (a) Quick wins — pre-flip, S effort each

A1. **Artifact not reproducible from repo (top finding; also solves T20 cleanly).**
ir/mch_ir.json frontend.source_files = [a_jettons_decl.mch, ...]. NOTHING in either repo
references a_jettons_decl — the emit dir was session-scratch, gone. THE version-controlled
contract can't be regenerated by any committed command. Meanwhile the language ALREADY has a
`priority DEC` directive (parser.py:251, compiler.py:88, ir_emit emits non-default) and zero
specs use it — the 'a_' hack exists only because emission is dir-glob-sorted
(ir_emit.py:320). Fix: committed manifest/emit script (specs/ + specs_decl/jettons.mch),
decl-jettons gets `priority 90` in-spec, drop filename dependence. Acceptance: emitted
bytes == committed artifact pre-edit, full gates post-regen. Kills plan §10 T20 +
prod-design §6.7 + a bus-factor hole.

A2. **run_two_phase double-executes every build for lookup-free matchers**
(BuildDriver.cpp:210-249): collect pass + final even with zero lookup nodes and zero host
fns (12/36 matchers; jetton builds re-parse both bodies in the dry pass). Fix:
`if (ref_lookups.empty() && ref_fns.empty())` → single pass with empty FilledLookupTable.
ref_fns must gate too (host fns fetch via the table, e.g. dedust_pool). Byte-identical
output; zero gate risk.

A3. **Twin CPP_* surface lists hand-synced ×3** (py_actions/py_classify/py_match_dump each
carry CPP_PARSERS/LOOKUP_KINDS/SHAPERS/PREDS/FNS). Fix: (i) one shared twins/cpp_surface.py,
or better (ii) exe `--surface` mode dumping the C++ registries as JSON, twins load it —
surface can never drift, and it doubles as the artifact-vs-registry check wave-0 wanted.
Recommend (ii).

A4. **Duplicate matcher names in prod artifact** (jetton_transfer ×3, jetton_burn/mint ×2 —
legacy builder-tier + decl twins in one artifact). Gates fine (index-keyed) but skip
lines/metrics are name-keyed → ambiguous shadow-mode counters. Fix at A1's manifest: exclude
the permanently-C++-skipped legacy jetton specs from the PRODUCTION artifact or suffix
names. Decide before shadow.

## (b) Redesigns worth doing before/at flip

B1. **Anchor prefilter for classify loop** (concretizes the dormant op_index/btype_index).
ClassifyCore.cpp:406-431: 36 full BFS traversals per trace, one per matcher, most touching
matchers whose anchor opcode never occurs. Design: per-trace inventory (opcode set + btype
set) built at init_block; empty intersection with anchor_opcodes/btypes → skip the matcher's
whole traversal; insert produced btype after each successful try_build (opcode inventory
static — produced blocks carry no opcode). Pred anchors stay full-scan. Semantically
airtight (skipping provable no-ops). 36 BFS → typically 3-6/trace; scales with matcher count
36→100+. Effort M-small, gate risk zero.

B2. **`flow` removal wave — plan §7 already ORDERS it, never scheduled.** Still alive:
8 flow stmts in specs (decl-jettons ×7, jvault ×1), FlowStmt through lexer/parser/AST/
ir_emit, FlowOp in BuildOutcome + codegen + CoreAction.flows that NOTHING consumes.
Pre-flip is the cheap moment (post-flip artifact changes need reindex-delta thinking).
Coordinated: specs + frontend + artifact regen + C++ plumbing delete + twins. Effort M.

B3. **Failure taxonomy at ClassifyResult seam — decide the enum BEFORE the actor slice
hard-codes strings.** Today: failure bool + free-text; skips = packed strings. Shadow mode's
value is attribution: matcher-skip / clean-reject / parse-null / lookup-miss (tier-1 vs
tier-2!) / lookup infra failure / engine fault / malformed trace. The tier-2 hit-rate
measurement prod-design §3 wants falls out free. Rendering stays adapter-side, twins
untouched. S-M now, M+ retrofit later.

## (c) Post-flip / measure-first / never

C1. **msg_envelope memoization or fused `.msg.field` accessor (biggest hot-spot found).**
ExprRuntime.cpp:251-287: EVERY `.msg` access builds a fresh 13-field Obj + nested 8-field tx
Obj (~21 string-keyed Fields, several RefInt256 allocs, 2 shared_ptr allocs), caller reads
ONE field. Specs have 74 `.msg.X` sites (65 = source/destination). Options: (i) lazy
per-Message envelope cache — S, no emitter change; (ii) emitter fuses attr(attr(x,"msg"),f)
→ rt_msg_field with Block fast path + generic fallback — M. Note: the §11.4a "accessor
dispatch INFEASIBLE" verdict does NOT cover this — the two-level path shape IS statically
visible in the IR; fused op keeps the runtime type check and exact fault parity. Do after
shadow profiling.

C2. **Int64 fast path in Value** — make_int64 heap-allocates RefInt256 for every envelope
int/literal/arith result. Inline small-int + lazy promotion is classic, but touches every
rt_* path — wide semantic-drift surface even gated. 3 ms/trace debug says speculative. L.
Park until a production profile demands it.

C3. **Generated-TU sharding + walker canonical() elision — not yet.**
builds_ir_generated.cpp = 211 KB at 36 matchers (~6 KB/matcher); single TU fine to ~100
matchers, then fixed-bucket shards. Walker's canonical() re-sorts are mostly no-ops
(substrate keeps canonical order) BUT insert_between deliberately doesn't sort (Python
parity) → invariant not universal → wholesale elision unsafe; needs the invariant closed
first. Payoff too small today.

C4. **IR-level optimization passes (const fold/CSE/dead-slot): never at current scale.**
Whole artifact = 138 build stmts; expressions 3-10 nodes. Nothing to fold. Reconsider only
at 10× matcher count AND profiling blames expr eval (C1/C2 would already cover).
